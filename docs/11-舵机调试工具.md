# 11 · 舵机调试工具（Seeed_RoboController）

> 对应官方 Wiki：[SO-Arm 舵机调试工具](https://wiki.seeedstudio.com/cn/lerobot_steering_gear_debugging_tool/)
>
> 图形化检测舵机、改 ID、写中位值、单舵机点动、寄存器读写、管理校准文件。
> 支持 Windows / Ubuntu / macOS。

这个工具是**排查舵机问题的救命稻草**：命令行校准报错、找不到舵机、ID 重复、
`Magnitude exceeds 2047`……最后往往都得靠它解决。

---

## 0. 阶段 B 到底要不要用它？

**结论：不是必须，但建议在整臂校准之前先做一次「只读检测」。**

官方主教程的立场很明确：

| 官方原文位置 | 说的是 |
| --- | --- |
| 「校准舵机并组装机械臂」章节开头 | 「如果你购买的是组装版机械臂，**请跳到校准机械臂步骤**」 |
| 「校准机械臂」章节末 | 「使用 Seeed Studio SoARM 系列快捷校准工具进行中位校准（**可选**）」 |
| FAQ「舵机 ID 错误、识别不到舵机或需要中位校准怎么办？」 | **出问题时**用这个工具 |

所以对**已组装整臂**来说，主流程是直接 `lerobot-calibrate`，这个工具属于备用手段。

### 但我建议做一次只读检测，原因是性价比

| 手段 | 层次 | 耗时 | 能发现什么 |
| --- | --- | --- | --- |
| `01-find-port.ps1` | 系统层 | 0.2 秒 | COM 口在不在（驱动 / 线缆问题） |
| `12-steering-tool.ps1 -Action scan` | 舵机层，**只读** | ~10 秒 | 舵机 ID 列表、有几个不响应、ID 是否重复 |
| `12-steering-tool.ps1 -Action gui` | 舵机层，只读 | ~30 秒 | 上面全部 + 电压 / 温度 / 力矩 / 状态 / 型号 |
| `03-calibrate.ps1` | 整臂层，读写 | 2~3 分钟 | 整体校准；**出错时只报错，不告诉你为什么** |

关键差别：`lerobot-calibrate` 跑到一半报 `Motor 'gripper' was not found`，
你无法区分是「6 号舵机线没插好」「6 号舵机 ID 不对」还是「6 号舵机坏了」。
先用 scan 扫一遍，10 秒就能把范围缩小到一个具体原因。

### 推荐顺序

```powershell
# 1. 系统层：确认 COM 口
powershell -ExecutionPolicy Bypass -File scripts\01-find-port.ps1

# 2. 舵机层：只读扫描（10 秒）—— 这一步就是回答「要不要用调试工具」
#    分别对 Follower 和 Leader 各扫一次
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action scan -Port COM9
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action scan -Port COM10

# 3. 整臂层：校准
powershell -ExecutionPolicy Bypass -File scripts\03-calibrate.ps1 -Arm follower
powershell -ExecutionPolicy Bypass -File scripts\03-calibrate.ps1 -Arm leader
```

**判读标准**：对每个臂，scan 应该列出 **ID 1~6 共 6 个舵机，且没有重复**。

> `-Port` 不传时会进交互式选择；传了就直接扫该口。
> ⚠️ 别用 `config.ps1` 里的占位值（本机 COM4/COM5 是蓝牙口）——所以脚本默认不自动套用配置里的串口。

### ⚠️ 现在【不要】做的操作

这些是**修复**手段，不是**检测**手段，会真的改动舵机内部状态。
没确认有问题之前不要动：

| 命令行动作 | **GUI 里的按钮名** | 实际写什么 | 后果 |
| --- | --- | --- | --- |
| `-Action middle` | 「串口中位校准」/「快速中位校准」 | `Torque_Enable(40) = 128` | **把当前位置写成中位 2048**，覆盖出厂中位与 `Homing_Offset` |
| `-Action change-id` | 「修改 ID」 | `ID(5)` | 改写舵机 ID；总线上有同 ID 舵机会被一起改掉 |
| `-Action disable` | 「串口失能电机」 | `Torque_Enable = 0` | 机械臂瞬间软掉 |
| `-Action quick` | 「快速校准」 | 含中位写入 | 同 middle |

> **实测事故记录（2026-10-16）**
>
> 在 GUI 里点了「快速中位校准」，对主臂 COM11 的 6 个舵机各执行了一次
> 「当前位置 → 2048」。结果：
>
> - `Homing_Offset` 从出厂值被改写成 `-572 / -783 / 141 / 1306 / 1483 / 89`
> - 结束时 `Torque_Enable` 被留成 **1（机械臂变硬，用手掰会顶着劲）**
> - 从臂 COM10 没点过，`Torque_Enable` 仍是 0，offset 仍是出厂值
>
> **完全可恢复**：`lerobot-calibrate` 的流程是
> `disable_torque()` → 让你摆到中位 → `set_half_turn_homings()`
> （内部先 `reset_calibration()` 把 offset 归零，**再按当前物理位置重写**）
> → 记录行程范围 → 覆盖写入 JSON 与舵机。
> **只要在正确的中间位跑一次 `lerobot-calibrate`，错误 offset 就被彻底覆盖。**
>
> **教训**：进 GUI 之前先分清按钮性质 ——
> 「检测」「中位测试」「读取」是**只读**；
> 带「**校准 / 写入 / 失能 / 修改 / 恢复出厂**」字样的全都是**写操作**。

## 0.5 什么时候【必须】用它

| 症状 | 对应动作 |
| --- | --- |
| `Motor 'gripper' was not found` | `-Action scan` 看总线上到底有哪些 ID |
| `Magnitude 30841 exceeds 2047` | `-Action gui` → 中位测试 → 写中位值 |
| 只接一个舵机却扫出别的编号 | `-Action change-id` 改回正确 ID |
| 机械臂软趴趴 / 完全不动 | `-Action diag -Port COM9 -Id 1` 看电压/温度/Status |
| 怀疑机械装配堵转 | `-Action gui` → 开力矩 → 单舵机点动观察电流 |
| 遥操作方向反 / 两臂读数不一致 | `-Action scan` 核对 ID，再回 `lerobot-calibrate` |

## 0. 一次性安装

```powershell
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action setup
```

脚本做的事：

1. clone `https://github.com/Seeed-Projects/Seeed_RoboController.git` → `tools\Seeed_RoboController`
2. 往本项目 venv 装依赖：
   - `PySide6-Essentials`（GUI 框架，只用 QtCore/QtGui/QtWidgets 三个模块）
   - `pyserial`
3. 跑 `python setup.py` 做环境自检

> 为什么装 `PySide6-Essentials` 而不是 `PySide6`？
> 官方 `requirements.txt` 写的是 `PySide6>=6.0.0`，那是元包，会连带
> `PySide6-Addons`（Qt 3D / WebEngine / Charts 等，好几百 MB）。
> 这个工具的实际 import 只有 QtCore/QtGui/QtWidgets，都在 Essentials 里。
> 另外**清华 PyPI 镜像没有 PySide6**，脚本会自动改走官方源 + 代理下载。

实测结果（2026-10-16）：

## 2. 能做什么

### 2.1 检测舵机是否正常

选好串口后，界面会扫描 **ID 1–20**。

- 1–6 号全部识别到 → 正常。
- 有 ID 没识别到 → 先查连线；重开一次界面再试；仍不行则可能是**ID 重复**。

> ID 重复的典型症状：明明只接了一个舵机，界面上却显示了别的编号。

### 2.2 重新写舵机 ID

⚠️ **串口是总线，写 ID 会命中总线上所有同 ID 的舵机。**
所以必须先把机械臂上的舵机线束**逐个拆开**，只留一个舵机接在驱动板上。

拆线顺序（从末端往底座）：6→5、5→4、4→3、3→2、2→1、1→驱动板。
拆完只剩一个舵机时，在界面里把它的 ID 改成正确的值。

> 实用技巧：**不拆机械臂也能改**——用一根三针线直接把驱动板和目标舵机单独连起来，
> 前提是它是总线上唯一通电的舵机。

### 2.3 写入中位值

1. 点「串口中位测试」，看机械臂姿势是否符合官方中位图。
2. 不符合 → 手动把机械臂摆到中位 → 点「串口中位校准」，
   当前位置会被写为 **2048** 存进舵机。
3. 点「串口失能电机」后机械臂会**软掉**，需要用手扶住。

> ### ★ 它为什么不可替代：128 命令改的是「绝对零点」★
>
> `lerobot-calibrate` 用的 `Homing_Offset` 是 **11 位符号幅值（±2047）**，
> 所以它只能把读数**平移 ±2047**。而舵机原生中位命令
> （寄存器 40 写 `128`）改的是**编码器的绝对零点**，修正范围不受这个限制。
>
> **实测证据（2026-10-17，主臂 wrist_flex）**：
>
> | | `Present` | `OFS` | 实测绝对编码器值 `= P + OFS` |
> | --- | --- | --- | --- |
> | 修正前 | -165（已到机械限位，上不去） | ~0（校准已归零） | **-1081** |
> | 点完「🎯 中位」后 | 2058 | 953 | **3011** |
>
> 绝对编码器值变化 **+4092 ≈ 一整圈（4096）**。
>
> **结论**：当某个关节「怎么转都进不了 `300~3795` 窗口」时——
> 先算一下需要的偏移量。中位读数取 `R_mid`，需要 `Homing_Offset = R_mid - 2047`；
> **如果 `|R_mid - 2047| > 2047`，LeRobot 的校准流程在数学上就不可能成功**，
> 必须用 Seeed GUI 的「🎯 中位」把这个舵机的绝对零点掰回来。
>
> 判据很简单：**如果一个关节转满行程仍然整体停在负数区（或整体 >4095），
> 那就是零点偏了整圈，去用 GUI，不要把时间浪费在重试校准上。**

> ### ⚠️ GUI 点「中位校准」时的最大坑：松手窗口
>
> Seeed 原版 `servo_quick_calibration.py` 的顺序是
> `失能所有舵机 → sleep(1) → 逐个写 128`。
> 那 1 秒里机械臂是**软的**，你一松手它就在重力下垮下去，
> 于是写进去的「当前位置」是**垮下去的姿势**，中位就记歪了。
>
> **安全做法（二选一）：**
>
> **(a) 用本项目的安全版包装脚本（推荐，等价但无松手窗口）**
>
> ```powershell
> # 先只读看一眼当前位置 / Homing_Offset / 力矩
> powershell -ExecutionPolicy Bypass -File scripts\16-middle-calibrate.ps1 -Arm follower -DryRun
> powershell -ExecutionPolicy Bypass -File scripts\16-middle-calibrate.ps1 -Arm leader  -DryRun
>
> # 正式写入：失能 -> 提示你摆姿势 -> 【按回车确认】-> 立刻写 128
> powershell -ExecutionPolicy Bypass -File scripts\16-middle-calibrate.ps1 -Arm follower
> powershell -ExecutionPolicy Bypass -File scripts\16-middle-calibrate.ps1 -Arm leader
> ```
>
> 同一个舵机命令（寄存器 40 写 128），但**写入发生在你确认姿势之后**，
> 中间没有「松手窗口」；并且写前写后都打印读数，能直接看出中位是否真变成 ~2048。
>
> **(b) 坚持用 GUI**，那顺序必须是：
> 先点「失能电机」→ 摆好姿势并**一直托住** → 再点「中位校准」→ 保持托住直到提示完成
> → 最后点「失能电机」。

> ### 中位校准到底解决什么、不解决什么
>
> 归一化公式（`motors_bus.py` 的 `_normalize`）：
> ```
> norm = (pos - range_min) / (range_max - range_min) * 200 - 100
> ```
> 遥操作映射：`pos_F = (norm + 100) / 200 * (max_F - min_F) + min_F`
>
> 把 `pos` 和 `min/max` 一起平移的 `Homing_Offset` 代进去，**会完全抵消**。
> 所以：
>
> | 问题 | 中位校准能修吗 | 真正该怎么做 |
> | --- | --- | --- |
> | 中位姿势不对、和官方参考图不一致 | ✅ 能 | 中位测试 → 中位校准 |
> | 原始读数跑飞导致 `Magnitude exceeds 2047` | ✅ 能 | 先中位校准，再跑 LeRobot 校准 |
> | 读数溢出编码器（如行程上限 4320） | ✅ 间接能 | 中位摆正中，行程就不会溢出 |
> | **遥操作幅度不准 / 从臂跟不上** | ❌ **不能** | 重跑 LeRobot 校准，**行程推到顶住限位** |
>
> **中位校准只对齐「零点」，不改变「跨度」。**
> 而跨度（`range_max - range_min`）才是决定遥操作幅度的唯一因素。
>
> 所以正确顺序永远是：
> **中位校准（本工具）→ LeRobot 校准（`14-calibrate-arm.ps1`，行程推到顶）→ 遥操作验证**

### 2.4 单舵机点动

开启力矩后拖进度条控制单个舵机。
注意：**不能拖到 0 或最大**，打印件会挡住行程，硬顶会堵转发热。

界面还会显示每个舵机的：

| 字段 | 含义 |
| --- | --- |
| Pos | 位置 |
| V | 电压 |
| T | 温度 |
| Spd | 速度 |
| Load | 力矩 |
| Cur | 电流 |
| Mov | 运动状态 |
| Model | 型号/权限 |
| Status | 正常 / 过流 / 过载 |

## 3. 命令行工具（不想开 GUI 时）

全部通过同一个脚本调用：

| 命令 | 作用 |
| --- | --- |
| `... -Action scan` | 扫描总线上所有舵机 ID |
| `... -Action scan -List` | 只列可用串口 |
| `... -Action change-id` | 改单个舵机 ID（交互式） |
| `... -Action center-test` | 中位测试 |
| `... -Action middle` | 按 LeRobot 校准文件写中位 |
| `... -Action quick` | 快捷校准 |
| `... -Action disable` | 失能电机（机械臂会软掉，扶好！） |
| `... -Action diag -Port COM9 -Id 3` | 读寄存器诊断单个舵机 |
| `... -Action limits -Port COM9` | 角度限位设置 GUI |
| `... -Action remote -Port COM9 -Port2 COM10` | 主从同步遥操作 |

示例：

```powershell
# 看看系统上到底有哪些串口
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action scan -List

# 按 Follower 的 LeRobot 校准文件写中位
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action middle -ArmType follower

# 按 Leader 的校准文件写中位
powershell -ExecutionPolicy Bypass -File scripts\12-steering-tool.ps1 -Action middle -ArmType leader
```

`-ArmType` 决定默认用哪个校准文件：

```
follower -> %USERPROFILE%\.cache\huggingface\lerobot\calibration\robots\<FollowerId>.json
leader   -> %USERPROFILE%\.cache\huggingface\lerobot\calibration\teleoperators\<LeaderId>.json
```

也可以 `-CalibrationFile <任意路径>` 指定别的。

## 4. 和 LeRobot 校准的关系

| 工具 | 存在哪里 | 什么时候用 |
| --- | --- | --- |
| `lerobot-calibrate` | `calibration\{robots,teleoperators}\<ID>.json` | 日常校准，主流程 |
| RoboController | 写进**舵机自身**的中位寄存器 + 可导出 LeRobot 格式 JSON | 舵机层面出问题时 |

两者是互补的：

- 机械臂轻微偏移、换 ID → 用 `lerobot-calibrate` 重新校准就够。
- 舵机中位乱了（`Magnitude exceeds 2047`）、ID 重复、找不到舵机 →
  必须先用 RoboController 在舵机层面修好，再回来做 `lerobot-calibrate`。

## 5. 典型排障流程

### 症状：`lerobot-setup-motors` 报 `Motor 'gripper' was not found`

1. `... -Action scan` 看总线上到底有哪些 ID。
2. 只有 1–5 没有 6 → 6 号舵机线没插好，或它的 ID 不是 6。
3. 只接了 6 号舵机却扫出别的 ID → 用 `-Action change-id` 改成 6。

### 症状：`Magnitude 30841 exceeds 2047 (max for sign_bit_index=11)`

1. 断电 → 重新上电。
2. 再跑一次 `lerobot-calibrate`；仍失败继续。
3. `... -Action gui` → 中位测试 → 摆到中位 → 写入中位值。
4. 再跑 `lerobot-calibrate`。

### 症状：前后两臂在同样姿势下读数不一致，遥操作方向反

1. 检查是不是 Leader 前三个关节减速比搞错了（SO101 与 SO100 不同）。
2. 用 GUI 逐个核对 ID 是否 1–6 且唯一。
3. 两个臂各自重新 `lerobot-calibrate`。

### 症状：机械臂软趴趴 / 完全不动

`... -Action diag -Port COM9 -Id 1` 看电压、温度、Status。
过流/过载 → 立即断电，检查是否堵转。
