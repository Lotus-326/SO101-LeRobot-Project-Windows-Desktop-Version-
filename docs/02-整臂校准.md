# 02 · 整臂校准（Leader / Follower）

> 校准是整条链路里最关键的一步：它让「同一个物理姿势」在 Leader 和 Follower
> 上产生**相同的关节读数**，从而让在一个臂上训练的策略能迁移到另一个臂。

---

## 1. 校准前准备

1. 关闭任何可能占用串口的程序。
2. 确认 `scripts\config.ps1` 里的 `FollowerPort` / `LeaderPort` 是真实 COM 口。
3. 打开官方校准参考图对照姿势（离线文档里存了图片链接）：
   - Leader：`_wiki\lerobot_so100m_new.md` 中 `cal_L1.jpg … cal_L6.jpg`
   - Follower：`cal_F1.jpg … cal_F6.jpg`
4. 机械臂通电、USB 连好。

---

## 2. 校准 Follower（从动臂）

> **用 `14-calibrate-arm.ps1`，不要用 `03-calibrate.ps1`。**
> `03` 包的是官方 `lerobot-calibrate`：它的行程记录靠「按回车停止」，
> 手一抖提前按下去就会得到 `min == max`，然后
> `ValueError: Some motors have the same min and max values` 整轮作废。
> `14` 包的是 `_tools\calibrate_arm.py`，改成固定时长自动窗口 + 实时达标提示，
> 从机制上消掉这个失败模式，并且会**自动备份旧校准**、**写一份完整日志**。

```powershell
cd D:\LeRobot          # 换成你自己的克隆路径
powershell -ExecutionPolicy Bypass -File scripts\14-calibrate-arm.ps1 -Arm follower
```

### 2.1 第 0 步：脚本自动检查「可编码窗口」（不用按键，15 秒实时显示）

脚本一上来会 `reset_calibration()` 把 `Homing_Offset` 归零，然后读**原始编码器值**。

为什么要检查：`Homing_Offset` 是 **11 位符号幅值**，幅值上限 2047；
而 offset = 原始值 − 2047，所以**按下回车那一刻**所有关节的原始值必须落在
`0 ~ 4094`。贴着边界也不行（摆姿势的过程中关节会微动），所以脚本要求更严的
**`300 ~ 3795`**。

不满足的关节会在屏幕上一行行实时刷新，你**用手轻轻转动**它，把数字转进
`300~3795` 并且**尽量贴近 2047** 即可。连续旋转的 `wrist_roll` 转过零点后
累计值会跑到 4095 以外（比如 7024），朝一个方向多转一两圈就能绕回来。

### 2.2 第 1 步：摆中位（按回车）

把机械臂摆成**各关节活动范围正中**的姿势，托住，然后按回车。

- 参考图：`cal_F1.jpg … cal_F6.jpg`（F6 = 夹爪）
  <https://files.seeedstudio.com/wiki/robotics/projects/lerobot/so101/cal_F1.jpg>
- **目标：每个关节的读数尽量贴近 2047。**
- ⚠️ 机械臂这时是**软的**，按回车时**手不要松开**——一松就会在重力下垮下来，中位就记歪了。

> **判断中位摆得准不准，有一个客观指标**：校准文件里
> `(range_min + range_max) / 2` 应该 ≈ **2047**。
> 本机从臂上一次校准的 `shoulder_lift` 是 `2028~4320`，中点 **3174**，
> 偏了 **+1127**（≈99°）——说明当时大臂被摆到了行程底部而不是中间，
> 结果行程上限超出编码器 0~4095，从臂在最高处会够不到主臂的动作。
> 脚本现在会在保存前把这种「偏心」列出来让你二次确认。

### 2.3 第 2 步：推满行程，推到【顶住机械限位】为止

依次把 1→6 每个关节**推到顶住机械限位**（来回 2~3 遍），**不用按键**。
屏幕实时显示每个关节的当前值、已记录行程、建议下限。

**推完所有关节后，按【回车】结束记录。**

> ⚠️ **这一步是整个校准里最容易出错、后果最严重的地方。**
>
> 遥操作走的是归一化：
> ```
> 主臂   : n     = (pos_L - min_L) / (max_L - min_L) * 200 - 100
> 从臂   : pos_F = (n + 100) / 200 * (max_F - min_F) + min_F
> ```
> 把两臂各自的「编码器 → 物理角度」线性关系代进去可以证明：
> **`Homing_Offset`（也就是中位值）会同时平移 `pos` 和 `min/max`，代入后完全抵消。**
> 所以决定遥操作准不准的，只有 `max - min`（行程跨度）有没有覆盖到
> **两臂相同的物理全程**。
>
> 只要有一臂没推到顶，跨度就被截断，于是：
> - **幅度错**：从臂走得比主臂多/少（增益误差）
> - **相位错**：两臂的「中位姿势」落进行程的不同位置
>
> 而且**每个关节的错法都不一样** —— 手感上就是「不准」而不是「整体偏一点」。
>
> 判据：行程显示达到「建议」值只是**及格线**，不是终点。
> 一定要推到**关节真的推不动了**才算推满。
> 万一行程确实偏小，脚本会在保存前明确列出来，并在汇总表标 `❌`。

`wrist_roll`（第 5 关节，连续旋转）会被自动设成全行程 0~4095，不用特意推。

> 担心推过头？不会。关节推到机械限位就物理上停住了，舵机此时力矩是关的，
> 人手推到底不会有额外风险。

## 3. 校准 Leader（领导臂）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\14-calibrate-arm.ps1 -Arm leader
```

流程与从臂完全相同，区别只有：

- 参考图换成 `cal_L1.jpg … cal_L6.jpg`
  <https://files.seeedstudio.com/wiki/robotics/projects/lerobot/so101/cal_L1.jpg>
- 校准文件写到 `...\calibration\teleoperators\so_leader\<LeaderId>.json`
- 主臂上电默认**力矩是关的**（本来就是软的），托住即可，不会有"突然变软"的惊吓

> ⚠️ 主臂前三个关节（shoulder_pan / shoulder_lift / elbow_flex）的减速比与从臂不同，
> 组装时若把 L1–L6 与 F1–F6 弄混，校准能过但遥操作方向/幅度会不对。
> 整臂是成品的话，这里只需目视确认关节没有被换过。

---

## 3.5 校准完成后：体检（只读，可随时重跑）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\15-preflight-calib.ps1
```

它会**只读**地打印两臂 6 个关节的：当前读数、Homing_Offset、力矩状态，
以及已有校准文件的 `range_min/range_max`、行程、**中点偏移**，并标出
「超出编码器」「行程偏小」「中位偏了」等问题。

> 只读保证：只用 `sync_read`/`read`，全程不写 EEPROM，
> 断开时走 `disable_torque=False`，不会在你不注意时把机械臂弄软。

## 4. 关于 ID

`config.ps1` 里：

```powershell
FollowerId = "my_awesome_follower_arm"
LeaderId   = "my_awesome_leader_arm"
```

**遥操作 / 采集 / 回放 / 评估必须使用同一个 ID**，否则会去找不存在的校准文件，
或者触发一次意外的重新校准。换 ID 就等于换一台机器人。

---

## 5. 重新校准

```powershell
# 方式一：先删旧文件再校准（推荐，最干净）
powershell -ExecutionPolicy Bypass -File scripts\03-calibrate.ps1 -Arm follower -Recalibrate

# 方式二：手动输入 c
powershell -ExecutionPolicy Bypass -File scripts\03-calibrate.ps1 -Arm follower
#   终端提示：Press ENTER to use provided calibration file ... or type 'c' and press ENTER
#   输入 c 回车 = 重新校准
```

**什么时候必须重新校准**：更换/维修过机械臂零件、舵机 ID 被改过、
出现 `Magnitude ... exceeds 2047`、出现无法解释的运动异常。

## 6. 散件组装才需要的舵机 ID 配置

整臂出厂已组装好、ID 已写好的话**跳过这节**。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\02-setup-motors.ps1 -Arm follower
```

脚本会按 `gripper → wrist_roll → wrist_flex → elbow_flex → shoulder_lift → shoulder_pan`
的顺序提示你：**每次只把一个舵机接到驱动板上**，然后回车。
（因为串口是总线，若存在重复 ID，改写会同时命中多个舵机。）

Leader 同理：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\02-setup-motors.ps1 -Arm leader
```

## 7. 校准阶段常见报错

| 报错 | 处理 |
| --- | --- |
| `Magnitude 30841 exceeds 2047` | 断电重上电再校准；仍失败则用 GUI 工具重写中位值（当前位置 → 2048）和舵机 ID |
| `Motor 'gripper' was not found` | 检查 6 号舵机连线与供电 |
| `Could not connect on port "COMx"` | 端口被占用 / 号变了 / 驱动板没上电 |
| 终端收不到 5 号舵机信号 | 官方说明属正常，继续 |
| 校准跑完后遥操作方向反了 | 大概率是 Leader 前三个关节减速比与 SO100 不同、校准姿势不对，重新校准 |
