# 05 · 数据采集

> **数据质量 > 数据数量。** 录制失败、遮挡、强光变化、背景干扰都会污染数据集；
> 宁可少录几个，也不要录脏数据。

---

## 0. 正式采集 Runbook（5 个固定点 × 每点 20 条 = 100 条）

> **执行顺序**：`19-marker-check`（定取景）→ `18-gonogo`（总检）→ `06-record`（采集）

### 0.1 第一步：逐点拍照，确认 5 个标记点都在画面内

```powershell
cd D:\LeRobot          # 换成你自己的克隆路径
powershell -ExecutionPolicy Bypass -File scripts\19-marker-check.ps1
```

引导式流程，每个点都是一次「放方块 → 回车拍照 → 看判据」：

```
把方块放到【标记点 1】，摆平，然后按回车拍照（r=重拍上一个  q=退出）:
  ✅ 标记点 1: x151-225(75) y248-333(86)  占画面 1.49%  中心 (188,290)  未贴边
把方块放到【标记点 2】，摆平，然后按回车拍照 ...
```

判据用的是**最大红色连通域**（不是所有红色像素的包围盒 —— 远处几个像素的
红色噪点会把包围盒撑到整个画面，让"贴边"判断完全失效）。

不合格的三种情况与处理：

| 判据输出 | 含义 | 处理 |
| --- | --- | --- |
| `物块贴到画面X边缘` | **被裁切** | 相机后移 / 抬高 / 调整俯仰，重拍该点 |
| `物块偏小（<0.15%）` | 太远或太小 | 相机靠近一些 |
| `没找到红色物块` | 不在画面内 / 被遮挡 / 太暗 | 检查摆放与光照 |

全部 5 点通过后会打印汇总表（含物块中心横向跨度、占比范围）和 `✅ YES`。
样张存到 `lerobot\outputs\captured_images\front_mark1..5.png`，随时可回看对比。

> ★ **这一步做完就把相机固定死** —— 之后整个采集过程都不要再碰它。
> 然后**用胶带把这 5 个点真正贴在桌面上**（拍照只是验证，标记要靠实物）。

### 0.2 第二步：GO / NO-GO 总检

```powershell
powershell -ExecutionPolicy Bypass -File scripts\18-gonogo.ps1
```

它检查 7 项（任何一项不过就打印 NO-GO 和原因，退出码 1）：

| # | 检查 | 不过的后果 |
| --- | --- | --- |
| 1 | 串口在不在、是不是 USB 转串口 | 连不上 |
| 2 | 两臂校准文件在不在 | 连不上 / 触发重校 |
| 3 | 舵机内校准 与 校准文件 是否一致 | record 中途弹 `Press ENTER... or type 'c'` |
| 4 | 主从臂行程幅度是否对齐（最大偏差 < 15%） | 遥操作幅度不准，白录 |
| 5 | 相机能否打开、物块是否可见且**未被裁切** | 策略学不到目标位置 |
| 6 | 磁盘剩余空间（×3 余量） | 录到一半爆盘 |
| 7 | 目标数据集是否已存在 | 意外接着旧数据录 |

**必须看到 `✅ GO` 才开录。** 100 条约 1.5 小时，中途发现相机歪了 / 校准漂了，
前面的就全废 —— 花 1 分钟自检远比返工划算。

#### 为什么不是固定 1 个位置

ACT 学的是 `π(动作 | 图像, 关节状态)` —— **方块在哪，信息本来就在图像里**。
固定位置时图像里除了手臂自己的运动几乎什么都不变，模型会走捷径：

> 「反正方块永远在那儿，我照轨迹回放就行」

于是它学成**轨迹回放器**而不是**抓取策略**：训练位置成功率很高，
但方块挪 5cm 就基本废。

**位置变化不是在"摊薄"数据，而是在逼模型真的用上视觉。**

| 方案 | 100 条怎么分 | 结果 |
| --- | --- | --- |
| 纯固定 1 个点 | 全在同一点 | ⚠️ 教会模型**忽略方块**，挪动即废 |
| **5 个固定点** | 每点 20 条 | ✅ 100 次技能演示 + 5 种视觉情境 |
| 连续随机 | 100 个点各 1 条 | 视觉覆盖最密，但每处只见过一次，可靠性略低 |

#### 为什么不是"每点条数不够"

**瓶颈从来不是"每个位置的条数"，而是"技能被演示了多少次"= 总条数。**
而且参数共享：位置 A 的那 20 条，也在教位置 B 同样的技能 —— 不是 5 个独立的模型。
所以 `5 × 20 = 100` 比 `1 × 50` 严格更强（同样的 100 次技能演示，外加 5 种视觉情境）。

> 时间紧张时 `5 × 10 = 50` 也能跑通（SwanLab 教程就是用 50 条），那是保底方案。

### 0.3 一个回合怎么演

```
┌─ 回合（被录，20s 上限）──────────────────────┐
│ 起点：夹爪张开，悬在方块上方偏后               │
│ ① 垂直下降，从正上方对准方块                   │
│ ② 捏主臂扳机 → 从臂夹爪合拢夹住                │
│ ③ 抬起，移到纸箱上方                           │
│ ④ 松开扳机 → 夹爪张开，方块落进箱               │
│ ⑤ 退回起点                                     │
│ ★ 立刻按【→】结束这一条 ★                     │
└───────────────────────────────────────────────┘
┌─ 复位（不录，随便动）────────────────────────┐
│ ① 伸手把方块摆到下一个标记点                   │
│ ② 方块放平（别立着）                           │
│ ③ 用主臂把从臂带回同一起点姿势                 │
│ ④ 按【→】进下一条                              │
└───────────────────────────────────────────────┘
```

### 0.4 录制纪律（都直接进数据，事后无法补救）

| 纪律 | 原因 |
| --- | --- |
| **手只碰主臂** | 从臂工作时上力矩、是硬的，用手碰会跟舵机对着顶 |
| **回合内人不要入镜** | 手/胳膊/鼠标都会被录成噪声特征（复位阶段随便动） |
| **看相机预览，不看真手** | 策略学到的就是相机视角 |
| **做完立刻按 →** | 死帧会教模型「大部分时间别动」 |
| **相机绝对不要碰** | 碰了之前采的全废 |
| **光照保持一致** | 白天/晚上混着采，策略会学歪 |

### 0.5 收尾三步（按 ESC 之前）—— 避免 `Overload error`

1. **松开主臂扳机** → 从臂夹爪张开，不要顶着任何东西
2. 把从臂摆到一个**放松姿势**（别停在"夹着方块"的状态）
3. 再按 **ESC**

> **实测报错（2026-10-16）**：
> ```
> RuntimeError: Failed to write 'Torque_Enable' on id_=6 with '0' after 6 tries.
> [RxPacketError] Overload error!
> ```
> 链条：`record()` 收尾 → `robot.disconnect()` → `disable_torque()` →
> 给从臂 6 号（夹爪）写 `Torque_Enable=0` → 舵机状态包带回 **Overload 位** →
> LeRobot 把「状态包有错误位」当写失败，重试 6 次后抛异常，**退出码 1**。
>
> **但数据是好的**：3 条数据与视频都已完整编码保存，且事后读回力矩确认
> 6 个舵机全是 `0`（`Torque_Enable=0` 其实写进去了，只是状态位让 LeRobot 抛了异常）。
> **这是虚警，不是数据损坏。** 根因是收尾时夹爪正死死夹着东西 → 堵转 → 过载位置位。

### 0.6 中断与续录

- 中途要停：按 **ESC**（会先把视频编码完再退，**不要直接关窗口**）
- 接着录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\06-record.ps1 -Resume -NumEpisodes 20
```

> `-Resume` 时 `-NumEpisodes` 填**还要再录几个**，不是总数。

**统计量（均值/方差）在录制结束后统一计算**，所以不要中途手动杀进程。

## 3. 录制中的键盘控制

**焦点必须在运行脚本的那个窗口上。**

| 键 | 动作 | 什么时候用 |
| --- | --- | --- |
| **→**（右箭头） | 提前结束当前 episode / reset，进入下一阶段 | 任务做完了，**立刻按**，别让死帧进数据 |
| **←**（左箭头） | **放弃**当前 episode 并重录 | **抓失败 / 方块掉了 → 就用它** |
| **空格** | **暂停 / 继续** | 舵机发烫要歇一会、有人打断、需要腾出手 |
| **`x`** | **急停**：丢弃当前条 + 结束会话 + 收尾释放力矩 | 异常运动 / 冒烟 / 要立刻停 |
| **ESC** | 结束整个会话，编码视频并（按配置）上传 | 正常收工 |

### 3.1 暂停（空格）到底做了什么

暂停期间：**不再录制新帧，但主从跟随继续**（你动主臂，从臂照样跟）。

这样设计有两个好处：

- 恢复时从臂**不会突然跳**（暂停期间它一直跟着主臂，没有积累位置差）
- **暂停的时长不会被算进 episode**（计时器做了补偿，不会一恢复就超时结束）

所以「暂停」的语义是：**把这段时间从演示里剪掉**，其余完全连续。

典型用法：

```
动作做到一半，舵机开始发烫
  → 按【空格】暂停
  → 松开主臂扳机让夹爪张开（卸掉负载，舵机就不再较劲）
  → 等它凉下来（可以顺手把方块摆正）
  → 再按【空格】继续，接着录同一条
```

> ⚠️ 暂停期间机械臂**仍然是硬的**（力矩保持）。如果要做需要失能力矩的操作，
> 用 `x` 急停，或者按 ESC 正常收工。

### 3.2 抓失败怎么办

| 情况 | 按键 |
| --- | --- |
| 方块掉了 / 没夹住 / 动作难看 | **←** 丢弃这一条，重录 |
| 舵机过载发烫 | **空格** 暂停 → 松开扳机卸负载 → 等凉 → 空格继续 |
| 已经录了几条，想歇口气 | **ESC** 收工，下次 `-Resume` 接着录 |
| 异常运动 / 要立刻停 | **`x`** 急停 |

### 3.3 这套按键是本项目打的补丁

原生 LeRobot 只有 `→` / `←` / `ESC` 三个键。空格与 `x` 是本项目加的：

- 改动文件：`lerobot\src\lerobot\utils\control_utils.py`（按键监听）
  和 `lerobot\src\lerobot\scripts\lerobot_record.py`（暂停计时补偿 + 收尾抗过载）
- 已固化为 `patches\0002-record-pause-and-emergency-stop.patch`
- **重新 clone 仓库后跑 `scripts\apply-patches.ps1` 即可复原**

顺带修了一个坑：收尾时若夹爪还死死夹着东西，`disable_torque` 会因舵机
`Overload` 状态位抛异常，导致**退出码 1、看起来像录制失败**（其实数据已保存）。
现在这个异常被兜住，收尾会照常完成（详见第 0.5 节）。

典型用法：

- 方块掉了 / 这次动作难看 → 先把机械臂摆回休息位，按 **←** 丢掉这段；
- 任务提前完成 → 按 **→** 跳过剩余等待时间。

> ### ★ 关键机制：复位阶段【不会被录进数据集】★
>
> 查 `lerobot_record.py`（第 537~548 行）：调用复位循环的 `record_loop(...)`
> **没有传 `dataset=` 参数**，所以那 30 秒只是给你动手的时间。
>
> 意味着**复位时你可以放心伸手进画面**把方块挪到下一个标记点、
> 把从臂摆回起点 —— 不会污染数据。
>
> 但反过来：**回合那段时间里，一切都会被录进去，包括你的手和胳膊。**

## 4. 参数一览

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `--dataset.episode_time_s` | 每个 episode 录制时长（秒） | 60 |
| `--dataset.reset_time_s` | episode 之间的环境重置时间（秒） | 60 |
| `--dataset.num_episodes` | 要录的 episode 总数 | 50 |
| `--dataset.fps` | 数据帧率 | 30 |
| `--dataset.video` | 是否编码成视频（关掉会存 PNG，极占空间） | true |
| `--dataset.vcodec` | `libsvtav1` / `h264` / `hevc` | libsvtav1 |
| `--dataset.push_to_hub` | 是否上传到 HuggingFace | true（本项目脚本默认改成 false） |

> **vcodec 选择建议**：默认 `libsvtav1` 压缩率高但 CPU 密集。
> 如果笔记本录制时掉帧，改成 `-VCodec h264` 换取流畅度（文件大一些）。

## 5. 存储位置

默认写到 HuggingFace 本地缓存：

```
%USERPROFILE%\.cache\huggingface\lerobot\<repo_id>\
```

例如 `seeedstudio123/m1_pick_cube` →
`%USERPROFILE%\.cache\huggingface\lerobot\seeedstudio123\m1_pick_cube`

如果想放到别的盘（例如 D 盘），加 `--dataset.root`：

```powershell
.venv\Scripts\lerobot-record.exe ... --dataset.root=D:\lerobot-data\m1_pick_cube
```

## 6. 采集质量规范

| 维度 | 要求 |
| --- | --- |
| 任务变化 | 在不同位置抓取并放进箱子（**唯一该变的维度**） |
| 数据规模 | **5 个固定点 × 每点 20 条 = 100 条**；时间紧张时 5 × 10 = 50 条保底 |
| 一致性 | 相机固定、抓取方式一致、目标物体始终可见 |
| 难度递进 | 先用 1 个位置做链路冒烟测试（约 20 条 + 短跑训练），再采正式的 5 × 20 |
| 黄金法则 | **只看屏幕视频画面来操作机械臂**，不要盯着真实物体 |

统计量（均值/方差）是在**录制结束后**统一计算的，所以：

- ❌ 不要中途手动暂停/终止进程；
- ✅ 要停就用 ESC，让它走完收尾。
- ✅ 中断了可以续录：`-Resume`（`num_episodes` 填**还要再录几个**，不是总数）。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\06-record.ps1 -Resume -NumEpisodes 20
```

## 7. 录制时的常见问题

| 现象 | 处理 |
| --- | --- |
| 方向键 / ESC 没反应 | 点一下终端窗口获取焦点；仍无效则降级 pynput：`.venv\Scripts\pip install pynput==1.6.8` |
| fps 很低、机械臂卡顿 | 降相机分辨率/FPS、换 `-VCodec h264`、相机直连 USB 3.0、关掉其它占 USB 带宽的设备 |
| `No valid stream found in input file` | PyAV 编码异常；试试 `-VCodec h264`，或检查是否装了残缺的 ffmpeg |
| 磁盘爆了 | 用 `-NoVideo` 只做调试；正式采集保持 `video=true` |
