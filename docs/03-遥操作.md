# 03 · 遥操作（Leader 带动 Follower）

遥操作是验证「校准是否正确 + 主从链路是否稳定」的第一道关卡。
**这一步跑不顺，后面的采集数据全是废数据。**

---

## 1. 只验证机械臂链路（不接相机）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\04-teleoperate.ps1 -NoCamera
```

对应底层命令：

```
lerobot-teleoperate ^
  --robot.type=so101_follower --robot.port=COM4 --robot.id=my_awesome_follower_arm ^
  --teleop.type=so101_leader  --teleop.port=COM5 --teleop.id=my_awesome_leader_arm
```

- 用手缓慢移动 Leader 的每个关节，Follower 应**实时跟随**。
- 观察：是否跟手、有无明显延迟、是否有某个关节反向或抖动。
- 退出：`Ctrl+C`。

## 2. 带相机预览

```powershell
powershell -ExecutionPolicy Bypass -File scripts\04-teleoperate.ps1
```

需要先在 `config.ps1` 里正确设置 `Cameras`（见 [04-相机接入.md](04-相机接入.md)），
并保持 `DisplayData = $true`。

预览窗口的作用是：**确认相机视野覆盖整个工作台、物体始终可见、相机固定牢靠**
—— 这正是采集数据前的必备检查。

## 3. 定时自动退出（脚本化验证）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\04-teleoperate.ps1 -NoCamera -Seconds 20
```

跑 20 秒自动停，适合快速冒烟测试。

---

## 4. 判读标准

| 观察 | 结论 |
| --- | --- |
| 6 个关节都跟手、方向一致、无明显延迟 | ✅ 可以进入数据采集 |
| 某个关节方向相反 | 该关节校准姿势不对 → 重新校准 |
| 整体延迟大、卡顿 | 换 USB 3.0 直连、关掉相机预览、降低相机分辨率/FPS |
| Follower 抖动/嗡嗡响 | 供电不足（换 5V 电源）、机械装配过紧 |
| Leader 完全无响应 | COM 口填错、Leader 未上电 |

## 5. 底层命令速查（不用脚本时）

```powershell
# 进入已激活环境
powershell -ExecutionPolicy Bypass -File scripts\shell.ps1

lerobot-teleoperate `
  --robot.type=so101_follower --robot.port=COM4 --robot.id=my_awesome_follower_arm `
  --teleop.type=so101_leader  --teleop.port=COM5 --teleop.id=my_awesome_leader_arm `
  --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30} }" `
  --display_data=true
```

> PowerShell 里 `--robot.cameras=` 的值请用**单引号包内层**（`fourcc: 'MJPG'`），
> 外层用双引号。这样 PowerShell 传给 exe 时才不会被转义搞乱。
> 脚本已经帮你处理好了，手敲命令时注意这一点。
