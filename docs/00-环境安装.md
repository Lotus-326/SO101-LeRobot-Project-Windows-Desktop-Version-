## 2. 一键安装

```powershell
cd "D:\机电创新实验室\智能装备实验室 m1机械臂抓取\LeRobot"
powershell -ExecutionPolicy Bypass -File scripts\setup-env.ps1
```

脚本依次做四件事：

1. 用 `D:\python\python.exe` 在项目下创建 `.venv`（Python 3.13）。
2. 装 `pip / setuptools / wheel`（走清华 PyPI 镜像）。
3. 装 **PyTorch 2.7.1 + cu128** 与 **torchvision 0.22.1 + cu128**
   （走官方 `download.pytorch.org` 直连；失败自动回退上海交大镜像）。
4. 在 `lerobot\` 里 `pip install -e ".[feetech,orbbec]"`
   —— `feetech` 是 STS3215 舵机 SDK，`orbbec` 是 Gemini 2 相机 SDK。

常用参数：

```powershell
-SkipTorch         # 只装 lerobot 依赖，不动 torch
-PypiMirror <url>  # 换 PyPI 镜像
-UseProxy          # 直连不通时才加，会让 pip 走 127.0.0.1:7897
```

实测耗时：Torch cu128 wheel 约 **3.27 GB**，直连约 2 MB/s → **25~35 分钟**；
加上其余依赖整体约 30~45 分钟。

## 3. 为什么选这个分支和版本

Seeed 仓库有两个重要分支：

| 分支 | 版本 | Orbbec 支持 | 结论 |
| --- | --- | --- | --- |
| `main` | 0.6.2 | ❌ 无 `cameras/orbbec/` | 不用 |
| `DepthCameraSupport` | 0.4.4 | ✅ `orbbec_color` / `orbbec_depth` | **本项目使用** |

```powershell
cd lerobot
git checkout DepthCameraSupport
git branch --show-current      # 应输出 DepthCameraSupport
```

校验注册是否正常：

```powershell
.venv\Scripts\python.exe -c "import lerobot.robots.so_follower, lerobot.teleoperators.so_leader as t; print('ok')"
```

## 3b. 打补丁（必做）

Seeed 的 `DepthCameraSupport` 分支是从上游快照拼出来的，有个会导致
**任何带 opencv 相机的命令都崩溃**的 bug（详见
[09-Windows排障FAQ.md](09-Windows排障FAQ.md) 的 C0 条目）。

本项目已把修补固化在 `patches\` 下：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\apply-patches.ps1
```

> **重新 clone `lerobot` 仓库之后必须再跑一次。**
> 当前状态确认：`git -C lerobot status --porcelain` 应显示
> `M src/lerobot/cameras/utils.py`。

## 4. ffmpeg（备用）

0.4.4 的数据集视频编码走 **PyAV**（`av` 包自带的 FFmpeg 库），
编码器 `libsvtav1` 由 PyAV 提供，因此**不装系统 ffmpeg 也能录数据**。

但保留一份命令行 ffmpeg 更方便排查（`ffprobe` 看视频、手工转码）：

- 已下载到 `tools\ffmpeg-master-latest-win64-gpl\bin\`（BtbN GPL 构建，含 libsvtav1）
- 所有 `scripts\*.ps1` 都会自动把它加到 `PATH`

验证：

```powershell
tools\ffmpeg-master-latest-win64-gpl\bin\ffmpeg.exe -hide_banner -encoders | findstr svtav1
```

## 6. 网络配置说明

| 用途 | 走什么 |
| --- | --- |
| git clone / git pull | git 全局 `http.proxy = http://127.0.0.1:7897` |
| pip（普通包） | 清华 PyPI 镜像，**直连**（不走代理） |
| PyTorch wheel | 官方 `download.pytorch.org/whl/cu128`，**直连**（`setup-env.ps1` 默认） |
| HuggingFace 模型/数据集 | 默认经代理直连；慢的话在 `config.ps1` 里把 `UseHfMirror` 改成 `$true` 走 `hf-mirror.com` |

### 实测带宽（2026-10，本机）

| 源 | 速度 | 结论 |
| --- | --- | --- |
| `download.pytorch.org`（直连） | **≈ 2.1 MB/s** | ✅ 采用 |
| `mirror.sjtu.edu.cn/pytorch-wheels` | ≈ 0.8 MB/s | 备用回退 |
| `mirrors.aliyun.com/pytorch-wheels` | ≈ 0.33 MB/s | ❌ 太慢 |
| `download.pytorch.org`（经 Clash 代理） | 会 SSL EOF / 卡死 | ❌ 不要走代理 |

所以 `setup-env.ps1` **默认直连**；只有在直连不通时才加 `-UseProxy`。

> ⚠️ PowerShell 5.1 的坑：**空字符串参数会被直接丢掉**。
> 所以脚本里不能写 `--proxy ""`（会变成 `--proxy <下一个参数>`，
> pip 直接报 `You must give at least one requirement to install`），
> 代理一律通过 `HTTP_PROXY/HTTPS_PROXY/NO_PROXY` 环境变量控制。

如果代理端口变了，改 `scripts\config.ps1` 的 `Proxy`，并同步：

```powershell
git config --global http.proxy http://127.0.0.1:<新端口>
git config --global https.proxy http://127.0.0.1:<新端口>
```

## 7. 脚本编码红线

Windows PowerShell 5.1 **没有 BOM 就按 GBK 解析** `.ps1`，中文会乱码，
个别汉字还会把引号「吃掉」导致语法错误。

所以：**每次编辑 `scripts\*.ps1` 之后，执行一次**

```powershell
python _tools\to_utf8bom.py scripts
```

（`_tools\to_utf8bom.py` 会递归给 `.ps1/.psm1/.bat/.cmd` 补 UTF-8 BOM。）
