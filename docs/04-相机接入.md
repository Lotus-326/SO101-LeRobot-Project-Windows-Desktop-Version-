# 04 · 相机接入（Orbbec Gemini 2 / 普通 USB 相机）

相机是策略的「眼睛」。原则很简单：

> **固定位置、固定角度、固定光照、目标物体始终在画面内。**

---

## 1. 先检测相机

```powershell
# 全部类型
powershell -ExecutionPolicy Bypass -File scripts\05-find-cameras.ps1

# 只查某一种
powershell -ExecutionPolicy Bypass -File scripts\05-find-cameras.ps1 -Backend orbbec
powershell -ExecutionPolicy Bypass -File scripts\05-find-cameras.ps1 -Backend opencv
```

输出内容包括：相机名、序列号 / 编号、USB 信息、默认流配置，
并在 `lerobot\outputs\captured_images\` 里留下**样张 PNG**（直接打开看画面）。

---

## 2. Orbbec Gemini 2（本项目主相机）

### 2.1 为什么必须用 `DepthCameraSupport` 分支

官方 `main` 分支**没有** `src/lerobot/cameras/orbbec/`，
只有 Seeed 的 `DepthCameraSupport` 分支提供 `orbbec_color` / `orbbec_depth` 两种相机类型。
本项目已经切到该分支并安装了 `[orbbec]` 额外依赖（`pyorbbecsdk2`）。

确认：

```powershell
cd lerobot
git branch --show-current          # DepthCameraSupport
..\.venv\Scripts\python.exe -c "import pyorbbecsdk; print('orbbec sdk ok')"
```

### 2.2 查到序列号

```powershell
powershell -ExecutionPolicy Bypass -File scripts\05-find-cameras.ps1 -Backend orbbec
```

输出里的 `Id` 就是 `serial_number_or_name`（形如 `CP9JA530003A`）。

### 2.3 写入 config.ps1

只取彩色（**数据采集推荐**，ACT 用彩色就够，数据量小一半）：

```powershell
Cameras = "{ orbbec_color: {type: orbbec_color, serial_number_or_name: 'CP9JA530003A', width: 640, height: 480, fps: 30, color_mode: rgb, warmup_s: 1} }"
```

彩色 + 深度（想做 RGB-D / 点云时用）：

```powershell
Cameras = "{ orbbec_color: {type: orbbec_color, serial_number_or_name: 'CP9JA530003A', width: 640, height: 480, fps: 30, color_mode: rgb, warmup_s: 1}, orbbec_depth: {type: orbbec_depth, serial_number_or_name: 'CP9JA530003A', width: 640, height: 400, fps: 30, depth_alpha: 0.2, warmup_s: 5} }"
```

> 参数提示
> - `depth_alpha`：深度图可视化缩放，从 `0.2` 起调。
> - 接 3 个以上深度相机时把 `fps` 降到 `15`。
> - 优先保持 `640x480`，兼顾稳定性与实时性。
> - Orbbec 深度流宽高比通常是 640×400。

### 2.4 Orbbec 常见问题

| 现象 | 处理 |
| --- | --- |
| `No Orbbec camera found for 'XXXX'` | 序列号写错；重跑 `05-find-cameras.ps1 -Backend orbbec` 拿正确 serial |
| `TimeoutError: Timed out waiting for frame` | 官方建议在 Linux 下增大 USBFS 缓存；**Windows 没有这个参数**，改为：拔插相机、换 USB 3.0 直连（不要 Hub）、降低分辨率/FPS |
| 相机被识别成多个 OpenCV 设备 | 正常。**最后插普通 USB 相机**，让它排在编号最后 |

## 3. 普通 USB / UVC 相机

```powershell
powershell -ExecutionPolicy Bypass -File scripts\05-find-cameras.ps1 -Backend opencv
```

输出里的 `Id`（0、1、2…）作为 `index_or_path`：

```powershell
Cameras = "{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30} }"
```

需要强制 MJPG（更高分辨率/更省 USB 带宽）：

```powershell
Cameras = "{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: 'MJPG'} }"
```

> ⚠️ 内层必须用**单引号**。因为 `config.ps1` 的 `Cameras` 是一个会被整段
> 传给 exe 的字符串，双引号会被 PowerShell 的转义规则破坏。

多相机：

```powershell
Cameras = "{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, side: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30} }"
```

### USB 带宽红线

- 相机**直连主板 USB 3.0**，不要接 Hub；两个相机不要共用同一个 Hub。
- 接在 USB 2.0 口上可能读不出图。
- MJPG 比 YUYV 省带宽；YUYV 会掉帧并拖慢主循环。

---

## 4. 混合使用（Orbbec + 普通相机）

```powershell
Cameras = "{ orbbec_color: {type: orbbec_color, serial_number_or_name: 'CP9JA530003A', width: 640, height: 480, fps: 30, color_mode: rgb, warmup_s: 1}, orbbec_depth: {type: orbbec_depth, serial_number_or_name: 'CP9JA530003A', width: 640, height: 400, fps: 30, depth_alpha: 0.2, warmup_s: 5}, side: {type: opencv, index_or_path: 8, width: 640, height: 480, fps: 30, fourcc: 'MJPG'} }"
```

插入顺序：**先 Orbbec，后普通相机**。

## 5.5 取景自检：采集前最值得做的一件事

> **物块必须完整在画面里，而且不能太小。**
> ACT 就是靠图像学「东西在哪」；目标物被裁掉一块，模型学到的位置信息就是残缺的，
> 成功率会明显偏低。SwanLab 教程的原话是：
> **「你应该仅通过查看相机图像就能完成这项任务。」**

```powershell
# 随手拍一张（不动机械臂、不写任何 EEPROM）
powershell -ExecutionPolicy Bypass -File scripts\17-snapshot.ps1

# 逐个位置各拍一张，文件名带标签，便于横向对比
powershell -ExecutionPolicy Bypass -File scripts\17-snapshot.ps1 -Label pos1
powershell -ExecutionPolicy Bypass -File scripts\17-snapshot.ps1 -Label pos2
...

# 拍完自动打开看图
powershell -ExecutionPolicy Bypass -File scripts\17-snapshot.ps1 -Label pos1 -Open
```

样张存到 `lerobot\outputs\captured_images\front_<标签>.png`，
终端会给出**量化判据**（而不是只让你用肉眼猜）：

```
[OK] front: shape=(480, 640, 3) dtype=uint8 mean=108.9 min=0 max=255
     画面尺寸 640x480；高饱和红色像素占比 0.37%  ← 物块可见，占比合理
     红色区域包围盒: x 340~382 (43px)  y 192~231 (40px)   占画面 0.56%
     红色区域没有贴边（未被裁切）
```

怎么读：

| 输出 | 含义 |
| --- | --- |
| `红色区域贴到画面X边缘` | **被裁切了** —— 相机后移 / 抬高，直到不再贴边 |
| `物块可能太小/不在画面内/被遮挡` | 红色占比 < 0.15%，把相机靠近一些或换个角度 |
| `画面几乎全黑` / `几乎全白` | 镜头盖 / 曝光 / 逆光问题 |
| `mean` 长期 > 230 | 逆光或过曝，尽量避开窗户 |

### 推荐的采集前检查流程

1. 把物块摆到计划里的**每一个位置**（本项目是 5 个），各拍一张
2. 逐张确认：**没贴边**、红色占比 ≥ 0.3%、放置盒也在画面内
3. 5 个位置都过关 → **固定相机，之后再也不要碰它**
4. 相机一动，之前采的数据集就作废了（视觉分布变了）

> ⚠️ 录制期间**人不要出现在画面里**（伸手扶臂、拿鼠标的手都会被拍进去，
> 变成策略要学的「噪声特征」）。

## 6. ⚠️ 相机键名的一致性红线

`front`、`side`、`orbbec_color` 这些**键名**会被写进数据集的 features。
训练、评估、回放时必须完全一致，否则报：

```
mean is infinity. You should either initialize with stats as an argument or use a pretrained model
```

**规则：采集数据用哪套 `Cameras`，训练和评估就必须用哪套。**
